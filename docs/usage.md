# 使用手册

## 概念

AudioBridge 有两个角色，任何一端都可以扮演：

- **发送端**：采集本机正在播放的系统声音，推流给对方（TCP 客户端）；
- **接收端**：监听端口，把收到的声音用本机扬声器/耳机播放（TCP 服务端）。

端口默认**固定为 48000**（两端一致，可在「高级」里改）。同一时刻只有一路
音频流；接收端有新连接请求而会话未结束时会被 `BUSY` 拒绝。

## 自动发现：不用填 IP（推荐）

接收端启动监听后，会在 UDP/48000 上应答局域网扫描；发送端点
**「扫描局域网设备」**，2 秒左右列出所有在线接收端（设备名 + IP），
点「连接」即自动开始发送。

- 电脑端也可以用命令行验证扫描：`audiobridge-cli probe --port 48000`；
- 扫描基于 UDP 广播，跨路由器/AP 隔离的网络不可达（企业网络常见），此时用
  下面的手动方式；
- 模拟器（NAT 网络）广播不可达，测试时请用手动 IP 或 USB 隧道。

## 场景一：手机看剧，电脑耳机听（局域网）

### 电脑端（接收）

1. 运行 `audiobridge.exe`；
2. 角色选择 **接收端（本机播放）**；
3. 点 **开始接收**（端口固定 48000）；
4. 状态显示「等待连接…」。

### 手机端（发送）

1. 安装 AudioBridge APK，打开；
2. Tab 选 **发送到电脑**；
3. 点 **扫描局域网设备** → 在列表中找到电脑 → 点 **连接**；
4. 首次发送：在系统弹窗中勾选并允许「录制/投射音频」；
5. 电脑端状态变为「已连接 <手机名>」，手机播放的声音即从电脑输出。

### 手动指定 IP（扫描不到时）

手机端「手动指定地址」里填电脑 IP（电脑端 `ipconfig` 查看 IPv4 地址），
端口 48000，点开始发送。

## 场景二：USB 数据线连接（推荐、更稳）

前提：手机开启「USB 调试」，电脑安装了 adb（Android platform-tools）并在 PATH 中。

1. 手机用数据线连接电脑，弹出的「允许 USB 调试」选择允许；
2. 电脑端 AudioBridge → 发送端 → **手动指定 IP / USB(ADB)（高级）** →
   点 **USB(ADB) 接入**：
   - 成功后状态提示「手机端目标填 127.0.0.1:48000」，并自动把目标 IP 改为 127.0.0.1；
   - 等价于执行了 `adb reverse tcp:48000 tcp:48000`；
3. 手机端「手动指定地址」：IP 填 **127.0.0.1**，端口 48000，开始发送。

> 原理：`adb reverse` 让手机访问自己的 `127.0.0.1:48000` 时，连接经 USB 线
> 转发到电脑的 48000 端口。传输不经过 WiFi，延迟与稳定性最佳。USB 隧道
> 场景广播扫描不可达，需手动填 127.0.0.1。
>
> 注意：此模式固定「手机发送 → 电脑接收」方向；想反向（电脑发送、手机收）
> 请用局域网 IP 直连。

## 场景三：电脑的声音发到手机（反向）

1. 手机端 Tab 选 **接收电脑声音** → 开始接收（记下端口）；
2. 电脑端角色选 **发送端（本机采集）** → 扫描（若手机在局域网可达）或手动填
   手机 IP 与端口 → 开始发送系统声音；
3. 电脑上播放的任何声音都会从手机扬声器/耳机输出。

## 测试源模式（自测）

手机端勾选 **「测试源模式」** 后，不采集系统声音，改为发送内置 440Hz 测试音：

- 用途 1：验证网络链路（ROM 不支持系统声音回采的设备/模拟器上也能测）；
- 用途 2：电脑端收到 rms>0 的音频即代表整条传输链路正常，可排查"听不到声音"
  是采集问题还是网络问题。
- 电脑端命令行接收统计：`audiobridge-cli listen --sink null` 结束时打印
  `RECEIVED bytes=... rms=...`，rms>0.001 表示收到真实信号。

## 访问令牌（可选）

两端「高级（访问令牌）」填相同字符串即可启用校验；接收端开启令牌后，
发送端令牌不符会被拒绝（AUTH_FAILED）。留空表示不校验。

## 命令行用法（Windows）

```bash
# 接收并播放
audiobridge-cli listen --port 48000 --sink speaker

# 采集本机系统声音发送
audiobridge-cli send --host 192.168.1.50 --port 48000

# 无声卡环境的自动化测试（tone 源 + null 输出）
audiobridge-cli send --host 127.0.0.1 --port 48000 --tone --seconds 5
audiobridge-cli listen --port 48000 --sink null --seconds 6
```

`listen` 结束时会打印 `RECEIVED bytes=... underruns=... dropped_bytes=...`
统计摘要，便于脚本化验证。

## 指标含义

| 指标 | 含义 |
| --- | --- |
| 缓冲 xms | 接收端抖动缓冲当前水位，稳定在目标水位附近为正常 |
| 欠载 n 次 | 缓冲耗尽被迫插静音的次数；偶发无感，频繁增大说明网络抖动大 |
| 溢出丢弃 x B | 接收太快/播放太慢被丢弃的数据；持续增长说明消费端跟不上 |
| 网络排队丢弃 | 发送端队列满时丢弃；说明网络带宽不足或对端卡顿 |

## 故障排查

**Q: 电脑端一直「等待连接…」**
- 检查两端 IP/端口；电脑防火墙可能拦截入站 48000 端口（首次监听时允许即可）；
- 手机与电脑必须在同一网段（部分路由器开了 AP 隔离会互相不可见）。

**Q: 连接成功但电脑没有声音**
- 电脑端音量滑条、系统音量、默认播放设备是否正确；
- 手机端媒体音量不能为 0；
- 接收端日志窗口有 WASAPI 相关报错则反馈 issue。

**Q: 声音断断续续**
- WiFi 信号弱 → 改用 USB 场景二；
- 把接收端「缓冲水位」从 80ms 调大到 120~200ms（增加延迟换稳定）。

**Q: 延迟太大（声画不同步明显）**
- 把缓冲水位调小（最低 20ms），前提是网络足够稳；
- 目前 v1 协议本身延迟 ~50ms 以内，主要延迟在抖动缓冲与播放缓冲。

**Q: Android 弹窗拒绝授权后无法再弹出**
- 系统「不再询问」时：设置 → 应用 → AudioBridge → 权限，
  或卸载重装后重新授权。
